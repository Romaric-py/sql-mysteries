SQL Murder Mystery

Trouverez-vous le coupable ?

Un meurtre a été commis à SQL City ! Le SQL Murder Mystery est conçu à la fois comme une leçon autonome pour apprendre les concepts et commandes SQL, et comme un jeu amusant permettant aux utilisateurs expérimentés de résoudre un crime intrigant.

Guide pas-à-pas pour les débutants en SQL

Si vous êtes déjà à l'aise avec le SQL, vous pouvez sauter ces explications et mettre vos compétences à l'épreuve ! Ci-dessous, nous introduisons quelques concepts de base du SQL, et juste assez de détails pour résoudre le meurtre. Si vous souhaitez une introduction plus complète au SQL, essayez Select Star SQL (en anglais).

Un crime a eu lieu et l'inspecteur a besoin de votre aide. Il vous a donné le rapport de la scène de crime, mais vous l'avez perdu. Vous vous souvenez vaguement qu'il s'agissait d'un meurtre (murder) qui a eu lieu le 15 janvier 2018 (20180115) et qu'il s'est déroulé à SQL City. Commencez par récupérer le rapport de scène de crime correspondant dans la base de données du commissariat.

Tous les indices de ce mystère sont enfouis dans une immense base de données, et vous devez utiliser le SQL pour naviguer dans ce vaste réseau d'informations. Votre première étape pour résoudre le mystère est de récupérer ce fameux rapport. Ci-dessous, nous allons vous expliquer les commandes que vous devez connaître ; dès que vous vous sentez prêt, vous pouvez commencer à adapter les exemples pour créer vos propres commandes SQL à la recherche d'indices — vous pouvez exécuter n'importe quelle requête SQL dans n'importe laquelle des boîtes de code, peu importe ce qu'elle contenait au départ.

Quelques définitions

Qu'est-ce que le SQL ?

SQL, qui signifie Structured Query Language (Langage de requête structurée), est un moyen d'interagir avec des bases de données relationnelles et des tables d'une manière qui nous permet, à nous humains, de récolter des informations spécifiques et pertinentes.

Une minute, qu'est-ce qu'une base de données relationnelle ?

Il n'y a pas de définition unique pour le terme base de données. En général, les bases de données sont des systèmes permettant de gérer de l'information. Elles peuvent imposer différents niveaux de structure aux données. Lorsque les données sont plus structurées, cela aide les humains et les ordinateurs à travailler avec elles plus efficacement.

Les bases de données relationnelles sont probablement le type de base de données le plus connu. Au cœur de celles-ci se trouvent des tables, qui ressemblent beaucoup à des feuilles de calcul (tableurs). Chaque colonne de la table a un nom et un type de données (texte, nombre, etc.), et chaque ligne de la table est une instance spécifique de ce que représente la table. La partie « relationnelle » vient de règles spécifiques sur la façon de connecter les données entre différentes tables.

Qu'est-ce qu'un ERD (Schéma relationnel) ?

ERD, qui signifie Entity Relationship Diagram (Diagramme Entité-Association ou schéma relationnel), est une représentation visuelle des relations entre toutes les tables pertinentes d'une base de données. Vous trouverez l'ERD de notre base SQL Murder Mystery ci-dessous. Le diagramme montre que chaque table a un nom (en haut de la boîte, en gras), une liste de noms de colonnes (à gauche) et leurs types de données correspondants (à droite, en majuscules). Il y a aussi des icônes de clés dorées, des flèches bleues et des flèches grises sur l'ERD. Une clé dorée indique que la colonne est la clé primaire de la table correspondante, et une flèche bleue indique que la colonne est une clé étrangère.

Clé Primaire (Primary Key) :
un identifiant unique pour chaque ligne d'une table.
Clé Étrangère (Foreign Key) :
utilisée pour référencer des données d'une table vers celles d'une autre table.
Si deux tables sont liées, les colonnes correspondantes, c'est-à-dire les identifiants communs des deux tables, sont connectées par une flèche grise dans le diagramme.

Qu'est-ce qu'une requête ?

Si vous deviez regarder les données de cette base, vous verriez que les tables sont immenses ! Il y a tellement de données qu'il est tout simplement impossible de parcourir les tables ligne par ligne pour trouver l'information dont nous avons besoin. Que sommes-nous censés faire ?

C'est là qu'interviennent les requêtes (queries). Les requêtes sont des instructions que nous construisons pour obtenir des données de la base. Elles se lisent presque comme de l'anglais naturel. Essayons quelques requêtes sur notre base de données. Pour chacune des boîtes ci-dessous, cliquez sur « Run » pour exécuter la requête. Vous pouvez modifier les requêtes directement ici sur la page pour explorer davantage. (Notez que les commandes SQL ne sont pas sensibles à la casse, mais il est conventionnel de les mettre en MAJUSCULES pour la lisibilité. Vous pouvez aussi utiliser des sauts de ligne et des espaces comme bon vous semble. La plupart des systèmes de bases de données exigent que vous terminiez une requête par un point-virgule (;) bien que le système de cette page web soit plus tolérant.)

Quels sont les éléments d'une requête SQL ?

Une requête SQL peut contenir :

  • Des mots-clés SQL (comme le SELECT et le FROM ci-dessus)
  • Des noms de colonnes (comme la colonne type ci-dessus)
  • Des noms de tables (comme la table person ci-dessus)
  • Des caractères génériques / jokers (tels que %)
  • Des fonctions
  • Des critères de filtrage spécifiques
  • Etc.

Les mots-clés SQL

Les mots-clés SQL sont utilisés pour spécifier des actions dans vos requêtes. Ils ne sont pas sensibles à la casse (majuscules/minuscules), mais nous suggérons d'utiliser des majuscules pour les mots-clés SQL afin de les distinguer facilement du reste de la requête. Voici quelques mots-clés fréquemment utilisés :

SELECT

SELECT nous permet de récupérer les données de colonnes spécifiques dans la base de données :

  • * (astérisque) : utilisé après SELECT pour récupérer toutes les colonnes de la table ;
  • nom_de_colonne(s) : pour sélectionner des colonnes spécifiques, placez leurs noms après SELECT et utilisez des virgules pour les séparer.
FROM

FROM nous permet de spécifier la ou les tables qui nous intéressent ; pour sélectionner plusieurs tables, listez les noms des tables et utilisez des virgules pour les séparer (nous verrons un peu plus loin comment relier correctement plusieurs tables entre elles).

WHERE

La clause WHERE dans une requête est utilisée pour filtrer les résultats selon des critères spécifiques.

Essayons certaines de ces commandes.

Le mot-clé AND (ET) est utilisé pour enchaîner plusieurs critères de filtrage afin que les résultats filtrés répondent à chacun des critères. (Il existe aussi un mot-clé OR (OU), qui renvoie les lignes correspondant à au moins l'un des critères.)

Si vous n'avez pas encore trouvé le bon rapport de scène de crime, cliquez sur « Show solution » ci-dessus, et remplacez le contenu de la boîte par la commande révélée (sans les /* et */). Si vous avez trouvé par vous-même la requête qui affiche l'unique rapport de scène de crime (en filtrant aussi sur la date `20180115`) au lieu des quelques rapports pour la même ville et le même type, alors félicitations et ignorez le mot « Incorrect ». Vous saurez quand vous l'aurez trouvé !

Caractères génériques (Wildcards) et autres fonctions pour les correspondances partielles

Parfois, vous ne connaissez qu'une partie de l'information dont vous avez besoin. Le SQL peut gérer cela. Les symboles spéciaux qui représentent des caractères inconnus sont appelés « wildcards » (jokers), et le SQL en prend en charge deux. Le plus courant est le joker %.

Lorsque vous placez un joker % dans une chaîne de caractères, le système SQL renvoie les résultats qui correspondent exactement au reste de la chaîne, et qui ont n'importe quoi (ou rien du tout) à l'emplacement du joker. Par exemple, 'Ca%a' correspond à Canada et California.

L'autre joker, moins couramment utilisé, est _ (tiret du bas). Celui-ci signifie « correspond au reste du texte, tant qu'il y a exactement un seul caractère à la position exacte du _, quel qu'il soit ». Ainsi, 'B_b' correspondra à 'Bob' et 'Bub', mais pas à 'Babe' ni à 'Bb'.

Important : Lorsque vous utilisez des jokers, vous n'utilisez pas le symbole = ; à la place, vous devez utiliser LIKE.

Le SQL prend également en charge les comparaisons numériques comme < (inférieur à) et > (supérieur à). Vous pouvez aussi utiliser les mots-clés BETWEEN (entre) et AND — et tout cela fonctionne aussi bien avec des mots (par ordre alphabétique) qu'avec des nombres.

Nous avons mentionné que les commandes SQL ne sont pas sensibles à la casse, mais les valeurs recherchées dans le WHERE avec = et LIKE le sont. Parfois, vous ne savez pas comment le texte est stocké dans la base de données. Le SQL fournit deux fonctions qui peuvent vous faciliter la tâche. Elles s'appellent UPPER() (majuscules) et LOWER() (minuscules), et vous devinerez facilement ce qu'elles font en explorant la boîte ci-dessous.

Les fonctions d'agrégation SQL

Parfois, les questions que vous voulez poser neconsistent pas simplement à trouver la ligne de données qui correspond à un ensemble de critères. Vous voudrez peut-être poser des questions plus complexes telles que « Qui est la personne la plus âgée ? » ou « Qui est la personne la plus petite ? ». Les fonctions d'agrégation peuvent vous aider à répondre à ces questions. En fait, vous avez déjà appris une fonction d'agrégation plus haut : COUNT.

Quel est l'âge de la personne la plus âgée possédant un permis de conduire ? Avec une petite quantité de données, vous pourriez le voir à l'œil nu, mais il y a des milliers d'enregistrements dans la table drivers_license. (Essayez COUNT si vous voulez savoir exactement combien !) Vous ne pouvez pas simplement parcourir cette liste pour trouver la réponse.

Voici quelques fonctions d'agrégation utiles fournies par SQL :

MAX
trouve la valeur maximale
MIN
trouve la valeur minimale
SUM
calcule la somme des valeurs de la colonne spécifiée
AVG
calcule la moyenne des valeurs de la colonne spécifiée
COUNT
compte le nombre de valeurs de la colonne spécifiée

Il existe un autre moyen de trouver les valeurs minimales et maximales, tout en voyant davantage de données sur la ligne correspondante. Vous pouvez contrôler l'ordre de tri des résultats que vous obtenez. C'est très intuitif : utilisez simplement ORDER BY suivi d'un nom de colonne. Par défaut, ORDER BY trie par ordre « ascendant / croissant » (du plus petit au plus grand, ou de A à Z), mais vous pouvez le préciser avec ASC pour croissant, ou inverser l'ordre avec DESC pour décroissant.

À ce stade, vous connaissez suffisamment de SQL pour identifier les deux témoins mentionnés dans le rapport de scène de crime. Essayez !

Faire des liens

Croiser plusieurs tables

Jusqu'à présent, nous avons posé des questions auxquelles on pouvait répondre en ne considérant que les données d'une seule table. Mais que faire si nous devons poser des questions plus complexes qui nécessitent simultanément des données provenant de deux tables différentes ?

Pour cela, nous allons lister plusieurs tables dans la clause FROM en les séparant par une virgule. Cette opération réalise ce qu'on appelle un produit cartésien : le système va combiner chaque ligne de la première table avec chaque ligne de la seconde table. Pour ne garder que les combinaisons qui ont du sens, nous allons filtrer le résultat dans la clause WHERE afin de faire correspondre les lignes liées entre elles.

La façon la plus courante de relier des tables est d'utiliser les colonnes de clé primaire et de clé étrangère en vérifiant leur égalité dans le WHERE. Référez-vous au schéma relationnel (ERD) plus haut si vous ne vous souvenez plus de ce que c'est, ou pour repérer les relations clés entre les tables de notre base de données (les flèches grises). Il est probablement plus facile de montrer comment cela fonctionne avec notre système interactif que de longuement l'expliquer.

Parfois, vous voudrez connecter plus de deux tables. Le SQL vous permet de lister autant de tables que vous le souhaitez dans le FROM, en ajoutant simplement les conditions de liaison correspondantes dans le WHERE à l'aide de l'opérateur AND.

Maintenant que vous savez comment croiser plusieurs tables, vous devriez être capable de trouver les transcriptions d'interrogatoires (table interview) pour les deux témoins que vous avez identifiés précédemment. Essayez !
